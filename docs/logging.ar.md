يكتب Mitra سجلاته إلى المخرج القياسي، لذا يعرض `docker compose logs` كل شيء:

```bash
docker compose logs -f mitra
```

الخادم السليم هادئ عن قصد: فهو لا يسجل افتراضيًا إلا ما يهم. ارفع المستوى أثناء تتبع مشكلة، ثم أعده إلى ما كان عليه عند الانتهاء.

## ضبط المستوى

```yaml
environment:
  MITRA_LOG_LEVEL: 'debug'
```

يتضمن كل مستوى كل ما في المستويات الأهدأ منه:

| `MITRA_LOG_LEVEL` | ما تحصل عليه |
| --- | --- |
| `error` | حالات الفشل فقط. |
| `warn` | وأيضًا المشكلات التي تجاوزها Mitra، مثل تذكير تعذّر تسليمه، أو خدمة ترميز جغرافي لم تُجب، أو مزوّد تسجيل دخول تعذّر الوصول إليه. |
| `info` *(الافتراضي)* | وأيضًا ما يهم في العمل اليومي: بدء التشغيل، وعمليات تسجيل الدخول، والحسابات التي رُبطت، والتغييرات التي وصلت من المزوّدين بالمزامنة، والتذكيرات المرسلة. |
| `debug` | وأيضًا كل طلب مع حالته ومدته، وكل مزامنة، ومتى تتسارع المزامنة أو تتباطأ مع فتح Mitra وإغلاقه، والجلسات، وتعديلات العناصر، والتخاطب مع خوادم CalDAV. |
| `trace` | وأيضًا كل استعلام لقاعدة البيانات وبيانات التقويم الخام. وهي كثيرة جدًا. |

يسجّل Mitra عند بدء تشغيله المستوى الذي يعمل به.

> [!NOTE]
> لا تُسجَّل كلمات السر والرموز والأسرار الأخرى أبدًا، في أي مستوى. لكن `debug` و`trace` قد يُظهران عناوين العناصر وبيانات التقويم، لذا راجع السجل قبل مشاركته.

## أي مستوى تستخدم

- عندما لا يتزامن تقويم، يُظهر `debug` كل مزامنة والطلبات المرسلة إلى CalDAV وNotion.
- عندما لا تصل التذكيرات، يسجّل `info` بالفعل كل تذكير عند إرساله، ويضيف `debug` كل محاولة تسليم والأجهزة التي أُزيلت.
- عندما تظهر لك صفحة خطأ، يسجّل `error` الخطأ مع تتبع المكدس، ويشمله المستوى الافتراضي `info`.
- عندما تحتاج إلى رؤية ما أرسله المزوّد بالضبط، يضيف `trace` البيانات الخام واستعلامات قاعدة البيانات. ولا تتركه مفعّلًا إلا لفترة قصيرة.
