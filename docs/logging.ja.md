---
title: ログ
description: MITRA_LOG_LEVEL で Mitra のログ出力量を選び、どのレベルがどの問題に役立つか。
---

Mitra は標準出力にログを出すので、`docker compose logs` ですべて見られます。

```bash
docker compose logs -f mitra
```

健全なサーバーはあえて静かにしています。デフォルトでは重要なことだけを記録します。何かを追いかけている間だけレベルを上げ、終わったら戻します。

## レベルを設定する

```yaml
environment:
  MITRA_LOG_LEVEL: 'debug'
```

各レベルには、それより静かなレベルのすべてが含まれます。

| `MITRA_LOG_LEVEL` | 出力される内容 |
| --- | --- |
| `error` | 失敗のみ。 |
| `warn` | 届けられなかったリマインダー、応答しなかったジオコーダー、接続できなかったサインインプロバイダーなど、Mitra が回避して動き続けた問題も。 |
| `info` *（デフォルト）* | 起動、サインイン、接続されたアカウント、プロバイダーから同期された変更、送信されたリマインダーなど、日常的に重要なことも。 |
| `debug` | すべてのリクエストのステータスと所要時間、各同期、Mitra の開閉に伴う同期頻度の変化、セッション、項目の編集、CalDAV サーバーとのやり取りも。 |
| `trace` | すべてのデータベースクエリと生のカレンダーデータも。量は膨大です。 |

Mitra は起動時に、動作しているログレベルを記録します。

> [!NOTE]
> パスワード、トークン、その他のシークレットはどのレベルでも決して記録されません。ただし `debug` と `trace` では項目のタイトルやカレンダーデータが出ることがあるので、共有する前にログに目を通してください。

## どのレベルを使うか

- カレンダーが同期しないときは、`debug` で各同期と CalDAV・Notion へのリクエストが見えます。
- リマインダーが届かないときは、`info` でも送信される各リマインダーが記録され、`debug` では各配信試行と除外されたデバイスも分かります。
- エラーページが出たときは、`error` がスタックトレース付きで記録しており、デフォルトの `info` にも含まれます。
- プロバイダーが送った内容を正確に見たいときは、`trace` が生データとデータベースクエリを追加します。短時間だけ有効にしてください。
