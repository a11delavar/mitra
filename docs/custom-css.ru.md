Вид Mitra задан обычным CSS, и поверх него можно добавить свой. Скройте то, чем никогда не пользуетесь, обведите рамкой сегодняшний день или дайте всему серверу свои цвета. Для этого есть два места: **Настройки → Общие → Свой CSS** для себя и, там где люди входят в систему, **Настройки → Администрирование → Свой CSS для всех** для всех на сервере.

> [!WARNING]
> До Mitra 1.0 любое обновление может изменить элементы, атрибуты и переменные, на которые нацелены ваши правила. Правило, которое работает сегодня, после обновления может перестать работать или начать что-то скрывать. Держите таблицу стилей короткой и смотрите на Mitra после каждого обновления.

## Ваша собственная таблица стилей

Откройте **Настройки → Общие** и введите CSS в поле под **Свой CSS**. Mitra применяет его прямо во время ввода, сохраняет через мгновение после того, как вы остановитесь, и он следует за вашей учётной записью на каждое устройство и в каждый браузер, где вы входите.

Переключатель рядом со **Свой CSS** выключает таблицу стилей, не теряя её, а [палитра команд](shortcuts.md) предлагает **Свой CSS: Выкл.** и **Свой CSS: Вкл.**.

`@import` удаляется при сохранении таблицы стилей: вставляйте таблицу целиком, а не ссылку на неё.

## Таблица стилей сервера

Там где люди входят в систему, администратор может изменить вид Mitra для всех на сервере: откройте **Настройки → Администрирование** и введите CSS в поле под **Свой CSS для всех**. Вы видите результат во время ввода, а все остальные при следующей загрузке Mitra. Её переключатель выключает её для всех, не теряя. Первый, кто входит на сервер, становится его администратором. Без входа ваша собственная таблица стилей и так доходит до всех, кто пользуется Mitra, поэтому она единственная.

Она подходит для того, что делает сервер вашим: его цветов, шрифта или [названия](configuration.md#name-your-instance), которое у него уже есть. Собственная таблица каждого человека идёт после неё, поэтому побеждает его таблица, где обе задают одно и то же.

## Ваше правило побеждает

Собственные правила Mitra лежат в каскадном слое с именем `mitra`, а ваши нет, поэтому ваше правило побеждает правило Mitra при любом селекторе. `!important` не нужен. Немногие объявления `!important` самой Mitra остаются сверху, потому что слои ранжируют их наоборот: они держат раскладку.

Чтобы убрать то, что задаёт Mitra, а не закрашивать поверх, задайте свойству значение `revert`. Так убирается подложка дней в виде месяца:

```css
mitra-weeks mitra-day {
	background: revert;
}
```

## Примеры

### Скрыть дни вне месяца

```css
mitra-weeks [data-outside] {
	visibility: hidden;
}
```

В [виде месяца](views/month.md) это скрывает дни до и после показанного месяца, их даты и фон. Записи на них остаются. `visibility` сохраняет сетку на месте, а `display: none` разорвал бы её. Увеличьте масштаб, чтобы дать дням самого месяца больше места.

### Рамка вокруг сегодняшнего дня

```css
mitra-weeks mitra-day[today] {
	outline: 2px solid var(--color-accent);
	outline-offset: -2px;
}
```

`outline`, а не `border`: рамка сделала бы день больше и сдвинула бы сетку.

### Ваши собственные цвета

```css
:root {
	--color-accent: light-dark(#2e7d32, #81c784);
	--border-radius: 8px;
}
```

`light-dark()` принимает цвет для светлой темы, затем цвет для тёмной. Всё, что Mitra окрашивает этими переменными, следует за ними, включая строку заголовка [установленного приложения](install-app.md):

| Переменная | Что она окрашивает |
| --- | --- |
| `--color-accent` | Сегодняшний день, выделенное, рамки фокуса и главные кнопки |
| `--color-background-seed` | Основу позади всего; диалоги берут свою от неё |
| `--color-surface` | Дни в видах и то, что лежит на основе, например палитру команд |
| `--color-text` | Текст |
| `--color-text-muted` | Второстепенный текст, например подсказки и время |
| `--color-error` | Ошибки и предупреждения |
| `--border-radius` | Углы кнопок, записей и большинства элементов управления |
| `--font-family` | Шрифт текста |

## Как найти, на что нацелиться

Инструменты разработчика в браузере показывают, что есть на странице: щёлкните что-нибудь правой кнопкой и выберите **Просмотреть код**. Собственные элементы Mitra называются `mitra-…`, например виды `mitra-days` (неделя), `mitra-weeks` (месяц), `mitra-months` (год), `mitra-timeline` и `mitra-table`, день `mitra-day`, запись `mitra-entry-segment` и боковая панель `mitra-sidebar`. Атрибуты сообщают факты, например `today`, `data-outside` и `data-date`.

Кнопки, поля, переключатели, меню и другие элементы управления держат своё устройство при себе. Добирайтесь до них через их части, например `mitra-switch::part(switch)`, и через переменные `--mitra-…`, которые они читают. Если нужно добраться глубже, попросите часть в [issue](https://github.com/a11delavar/mitra/issues).

## Что лучше не трогать

Несколько вещей держат Mitra вместе, и их изменение её ломает:

- `display` или `position` у `mitra-day` или у `.entries` внутри вида: они стоят на сетке, общей для всего вида, и без неё вид недели становится очень медленным.
- Переменные, которые начинаются с `--_`: они меняются в каждом кадре масштабирования, и если их задать, они будут ему мешать.
- Размер записи: её заголовок выбирает раскладку по её ширине, поэтому размер, заданный снаружи, может её переключить.
- `all: unset` отменяет и скрытие, поэтому добавьте рядом `[hidden] { display: none }`.

## Когда правило прячет путь назад

Добавьте к адресу `?css=off`, например `https://mitra.example.com/?css=off`. Тогда Mitra загрузится один раз без обеих таблиц стилей, и вы сможете открыть **Настройки** и исправить свою. Администратор так же исправляет таблицу для всех.

## Прежде чем вставить

Таблица стилей не выполняет код, но может загружать адреса, и написанная для этого таблица может отправить им то, что у вас на экране. Вставляйте только CSS, который понимаете. Ваша собственная таблица стилей доходит только до вас, а таблица сервера до всех на нём.

## Поделитесь своей

Под полем кнопка **Поделиться на GitHub** открывает новое обсуждение в категории [Custom CSS](https://github.com/a11delavar/mitra/discussions/categories/custom-css), где уже есть ваша таблица стилей. Напишите, что она делает, добавьте снимок экрана, если её видно, и опубликуйте. Таблица стилей, слишком длинная для ссылки, вместо этого копируется в буфер обмена, чтобы вы вставили её в обсуждение. В этой категории можно найти и таблицы стилей, которыми поделились другие: прочитайте их, прежде чем вставлять.
