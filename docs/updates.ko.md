실행 중인 버전보다 새로운 버전이 있으면 Mitra가 알려 줍니다. 스스로 업데이트하지는 않으며, 새 버전을 받을지는 직접 정합니다.

## 업데이트 표시

새로운 버전이 있으면 사이드바의 로고에 작은 점이 나타납니다. 인스턴스 이름을 클릭해 **정보**를 열면 실행 중인 버전과 커밋, 그리고 새로운 내용으로 가는 링크를 볼 수 있습니다. 그곳의 **복사**를 누르면 버전 정보가 복사되는데, 버그를 신고할 때 바로 이 정보가 필요합니다.

[명령 팔레트](shortcuts.md#command-palette)의 **새로운 기능**에는 모든 버전의 변경 사항이 나와 있습니다. 서버가 업데이트되면, 업데이트 전부터 열려 있던 탭마다 Mitra가 **업데이트를 마치려면 새로 고침하세요**라고 안내합니다.

릴리스(`latest`, `0.6` 또는 정확한 버전)를 실행 중이라면 최신 릴리스를 알려 줍니다. `dev` 이미지를 실행 중이라면 `main`의 최신 커밋을 알려 주고, 그 커밋이 얼마나 앞서 있는지도 알려 줍니다.

## 확인이 보내는 내용

브라우저가 아니라 서버가 하루에 몇 번 GitHub에 새로운 버전이 있는지 묻습니다. 이 요청에는 모든 요청에 들어가는 정보, 즉 IP 주소와 사용자 에이전트에 담긴 실행 중인 버전 외에는 인스턴스에 관한 정보가 전혀 담기지 않습니다. 원격 측정도, 식별자도, 집계도 없습니다.

서버가 GitHub에 연결하지 못하면 한 번만 로그에 남기고 그 뒤로는 조용히 있습니다.

확인을 완전히 끄려면 `MITRA_UPDATE_CHECK`를 `off`로 설정하세요(`false`, `0`, `no`도 됩니다).

```yaml
environment:
  MITRA_UPDATE_CHECK: 'off'
```

## 이미지 태그 고르기

태그에 따라 새 버전으로 얼마나 빨리 옮겨 갈지가 정해집니다.

| 태그 | 받게 되는 버전 |
| --- | --- |
| `latest` | 최신 릴리스입니다. |
| `0.6` | 최신 `0.6.x` 릴리스입니다. 수정 사항은 받지만 새 마이너 버전은 받지 않습니다. |
| `0.6.0` | 정확히 그 버전입니다. |
| `dev` | `main`의 최신 커밋으로, 릴리스되기 전에 새 기능을 써 보기 위한 것입니다. |

1.0 전까지는 새 마이너 버전(0.6에서 0.7로)이 사용 중인 기능을 바꿀 수 있습니다. 그 시점을 직접 고르고 싶다면 `0.6`을 쓰다가 준비가 되었을 때 옮겨 가세요. 모든 태그는 [GitHub](https://github.com/a11delavar/mitra/pkgs/container/mitra)에 나와 있습니다.

## Mitra 업데이트하기

새 이미지를 받고 컨테이너를 다시 만드세요.

```bash
docker compose pull
docker compose up -d
```

데이터는 마운트한 폴더에 있으므로 그대로 남습니다. 새 버전이 데이터베이스를 바꾸면 Mitra가 시작할 때 데이터베이스를 업데이트하므로, 직접 손댈 일은 없습니다. [Watchtower](https://containrrr.dev/watchtower/) 같은 도구를 쓰면 이 작업을 정해진 주기에 따라 자동으로 할 수 있습니다.

어떤 버전을 받을지는 [이미지 태그](#choose-an-image-tag)에 따라 달라집니다. 새 마이너 버전으로 옮기기 전에 [릴리스 노트](https://github.com/a11delavar/mitra/releases)를 읽어 보는 것이 좋습니다.
