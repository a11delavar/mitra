---
title: 日志
description: 用 MITRA_LOG_LEVEL 设置 Mitra 记录多少日志，以及排查不同问题时该用哪个级别。
---

Mitra 把日志写到标准输出，所以用 `docker compose logs` 就能看到全部内容：

```bash
docker compose logs -f mitra
```

运行正常的服务器刻意保持安静：默认只记录重要的信息。排查问题时调高日志级别，排查完再调回来。

## 设置级别

```yaml
environment:
  MITRA_LOG_LEVEL: 'debug'
```

级别越往下，记录得越详细，每个级别都包含它上面各级别的全部内容：

| `MITRA_LOG_LEVEL` | 记录的内容 |
| --- | --- |
| `error` | 仅记录故障。 |
| `warn` | 另外记录 Mitra 已自行应对的问题，比如无法送达的提醒、没有响应的地理编码服务，或者连接不上的登录服务提供商。 |
| `info` *（默认）* | 另外记录日常的重要事件：启动、登录、账号连接、从服务商同步来的改动，以及已发送的提醒。 |
| `debug` | 另外记录每个请求及其状态和耗时、每次同步、同步因有人打开或关闭 Mitra 而加快或放慢的时刻、会话、条目编辑，以及与 CalDAV 服务器之间的通信。 |
| `trace` | 另外记录每一条数据库查询和原始日历数据，内容非常多。 |

Mitra 启动时会在日志中写明当前使用的级别。

> [!NOTE]
> 无论在哪个级别，密码、令牌和其他机密信息都不会被记录。但 `debug` 和 `trace` 仍可能包含条目标题和日历数据，所以分享日志之前，请先检查一遍。

## 该用哪个级别

- 日历不同步时，`debug` 会显示每次同步，以及发往 CalDAV 和 Notion 的请求。
- 收不到提醒时，`info` 已经会在每条提醒发出时记录下来，`debug` 还会补充每一次投递尝试，以及哪些设备已被移除。
- 看到错误页面时，`error` 会记录该错误及其堆栈跟踪，默认的 `info` 级别也包含这些内容。
- 需要确切查看服务商发来了什么时，`trace` 会额外记录原始数据和数据库查询。只在短时间内开启它。
