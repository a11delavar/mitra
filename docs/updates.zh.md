---
title: 更新
description: Mitra 如何告诉你有新版本、更新检查会发送什么、如何关闭检查，以及如何更新。
---

有新版本发布时，Mitra 会告诉你。但它从不自行更新：是否拉取新版本，由你决定。

## 更新提示

有新版本时，侧边栏中的 Logo 上会出现一个小圆点。点击你的实例名称，打开 **关于**，就能看到你正在运行的版本和提交，以及指向更新内容的链接。在那里点 **复制**，可以复制版本信息，提交 bug 报告时正需要这些信息。

[命令面板](shortcuts.md#command-palette)中的 **更新内容** 列出了每个版本的改动。服务器更新后，在更新之前就已打开的标签页中，Mitra 会提示你 **重新加载以完成更新**。

如果你运行的是正式版本（`latest`、`0.6` 或某个确切的版本号），Mitra 会提示最新的正式版本。如果你运行的是 `dev` 镜像，它会提示 `main` 分支上的最新提交，并告诉你当前版本落后了多少。

## 更新检查会发送什么

每天，服务器（而不是你的浏览器）会向 GitHub 询问几次是否有新版本。除了任何请求都会带有的信息，即你的 IP 地址和 User-Agent 中的当前版本号之外，这个请求不包含任何关于你的实例的信息。没有遥测，没有标识符，也没有统计数据。

如果服务器无法连接 GitHub，它只会在日志中记录一次，之后不再重复。

要彻底关闭更新检查，请把 `MITRA_UPDATE_CHECK` 设为 `off`（也可以用 `false`、`0` 或 `no`）：

```yaml
environment:
  MITRA_UPDATE_CHECK: 'off'
```

## 选择镜像标签

标签决定了你跟进新版本的积极程度。

| 标签 | 你会得到 |
| --- | --- |
| `latest` | 最新的正式版本。 |
| `0.6` | 最新的 `0.6.x` 版本：包含修复，但不会升级到新的次版本。 |
| `0.6.0` | 正好是这个版本。 |
| `dev` | `main` 分支上的最新提交，适合在新功能正式发布前抢先试用。 |

在 1.0 之前，新的次版本（比如从 0.6 到 0.7）可能会改变你所依赖的功能。如果你想自己决定何时升级，就使用 `0.6`，等准备好了再切换。所有标签都列在 [GitHub](https://github.com/a11delavar/mitra/pkgs/container/mitra) 上。

## 更新 Mitra

拉取新镜像，然后重新创建容器：

```bash
docker compose pull
docker compose up -d
```

你的数据保存在挂载的文件夹中，所以不会丢失。如果新版本改变了数据库结构，Mitra 会在启动时自动更新数据库，你完全不用自己动手。[Watchtower](https://containrrr.dev/watchtower/) 等工具可以按计划自动帮你完成这些步骤。

你会更新到哪个版本，取决于你的[镜像标签](#choose-an-image-tag)。在升级到新的次版本之前，最好先读一读[版本说明](https://github.com/a11delavar/mitra/releases)。
