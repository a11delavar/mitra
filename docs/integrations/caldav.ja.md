---
title: CalDAV
description: Nextcloud、Radicale、Fastmail、mailbox.org など任意の CalDAV サーバーを接続し、予定とタスクを双方向に同期します。
---

CalDAV は、ほとんどのカレンダーサーバーが話すオープンな標準規格です。アプリから CalDAV アカウントを接続するだけで、サーバー側の設定は不要です。Mitra が予定とタスクを双方向に同期します。

カレンダーはあなたのサーバーに残るので、スマートフォンのカレンダーなど、他の CalDAV アプリからも同じ項目が見えます。これが、Mitra だけが開ける [Mitra カレンダー](mitra.md)との違いです。

## アカウントを接続する

1. サイドバー下部の**連携を追加**を選び、**CalDAV**を選びます。
2. フォームに入力します。
   - **サーバー URL** は `https://caldav.example.com` のような、サーバーの CalDAV アドレスです。主なプロバイダーのアドレスは[下の表](#server-urls-for-common-providers)にあります。
   - **ユーザー名** は通常、アカウント名またはメールアドレスです。
   - **パスワード** はアカウントのパスワード、またはプロバイダーが発行するアプリパスワードです。
3. **接続**を押します。Mitra がアカウントのカレンダーをすべてオンの状態で一覧し、「予定 · タスク」のように各カレンダーが保持できるものを示します。
4. 不要なものをオフにして **保存**を押します。

Mitra は残したカレンダーをインポートし、開いている間は10秒ごとに同期します([同期の仕組み](README.md#how-syncing-works)を参照)。

あとでパスワードを変更するには、サイドバーのアカウントの **⋯** メニューで**編集**を選び、新しいパスワードを入力して**保存**を押します。サーバー URL とユーザー名はそのままです。別のアカウントの場合は、個別に接続してください。

## 主なプロバイダーのサーバー URL

プロバイダーの CalDAV アドレスを渡せば、Mitra がそこからカレンダーを見つけます。

`https://<your-radicale>/<user>/` のようにアドレスがユーザーを指す場合、Mitra はあなた自身ではなくそのユーザーのカレンダーを、サーバーが共有している範囲で一覧します。アドレスごとに個別に接続してください。

| プロバイダー | サーバー URL |
| --- | --- |
| Nextcloud | `https://<your-nextcloud>/remote.php/dav` |
| Radicale | `https://<your-radicale>/` (or `.../<user>/`) |
| Fastmail | `https://caldav.fastmail.com/` |
| mailbox.org | `https://dav.mailbox.org/` |
| Baïkal | `https://<your-baikal>/dav.php` |

Google カレンダーと iCloud も CalDAV を話しますが、通常のパスワードは使えません。Google は独自のページでサインインさせ、Apple はアプリ用パスワードが必要です。[Google カレンダー](google.md)と [Apple カレンダー](apple.md)にあるように、それぞれ専用のタイルを使ってください。

## 同期されるもの

サーバー上の各カレンダーが、Mitra の1つのカレンダーになります。サーバーが許す範囲で、予定、タスク、またはその両方を保持します。ほとんどのサーバーは両方を許します。一方しか受け付けないカレンダーでは、新しい項目は常にその種類になります。

サーバーが保持する範囲で、Mitra が項目について保存するものはすべて同期されます。

- 終日・複数日にまたがる項目、場所、説明、色、リマインダー。
- 項目が予定ありか空きか、および公開範囲。
- タスクのステータスと進捗。
- [参加者](../participants.md)。招待の送信と返答の回収はサーバーが行います。
- [サブタスク](../subtasks.md)と[依存関係](../dependencies.md)。
- [添付ファイル](../attachments.md)。同じカレンダーの他のアプリにもファイルが見え、それらが追加したファイルも Mitra に表示されます。

> [!NOTE]
> 他のカレンダーアプリは個々の項目の色名しか読み取らないため、項目の色は最も近い色名で表示されます。たとえば Mitra の青は `steelblue` になります。Mitra は正確な色を保持し、他の Mitra インストールも読み戻せますが、色を破棄する Google 経由を除きます。

繰り返しの項目はサーバー上でも1つのシリーズのままです。1つの回を変更すると、Mitra は**この項目**、**これ以降の項目**、**すべての項目**のどれを指すか尋ね、それに合わせてシリーズを変更します。

タスクはスケジュールと[期日・見積もり](../planning.md#schedule-constraints-and-planning)を保ちます。サーバー上では次のように保存されます。

- 開始は `DTSTART`。
- 長さは `ESTIMATED-DURATION`。タスクに割り当てられた時間、または開始が未定の間は見積もり。
- 期日は `DUE`。

開始があり長さのないタスクは「時点」です。

閲覧のみで共有されたカレンダーは、読み取り専用とマークされます。名前の変更、色の変更、並べ替え、非表示は可能です。[読み取り専用カレンダー](../calendars.md#read-only-calendars)を参照してください。

## 予定ありの対応可能時間

**予定あり**にした[対応可能時間](../availability.md)は、そのカレンダーに予定ありの予定として追加されるので、スマートフォンでも、あなたを招待しようとする人にも、その時間が埋まっているように見えます。設定は不要です。

- 予定ありの対応可能時間はそれぞれ、同じ時刻と繰り返しルールを持つ予定ありの繰り返し予定になります。名前は対応可能時間の名前(なければ「予定あり」)、場所と公開範囲(**非公開**など)を引き継ぎます。
- Mitra の中ではこれらの予定ではなく対応可能時間自体が表示されるので、時間が二重に表示されることはありません。
- Mitra はこれらの予定を対応可能時間と一致させ続けます。他のアプリで変更・移動・削除されても、次の同期で元に戻します。
- 対応可能時間を再び**空き**にする、削除する、そのカレンダーをオフにする、アカウントを削除する、のいずれかで予定も消えます。対応可能時間を別のカレンダーに移すと、予定も一緒に移ります。
- タスクしか保持できないカレンダーや、書き込み権限のないカレンダーには予定は作られません。

> [!NOTE]
> 予定ありの対応可能時間の、ある1日だけへの変更は引き継がれません。予定は繰り返しルールに従い続けるので、移動や短縮した日も、他の人にはいつもの時間のまま見えます。

これは、同じく CalDAV で接続する [Google カレンダー](google.md) と [Apple カレンダー](apple.md) でも同じように動作します。

## トラブルシューティング

- カレンダーが見つからない場合は、オフになっています。接続時にオフにしたカレンダーと、あとからサーバーに作られたカレンダー(Mitra はオフの状態で追加します)がこれに当たります。アカウントの **⋯ → 編集**でオンにして**保存**を押してください。そこにある**更新**は、前回の同期以降にサーバーに作られたカレンダーを一覧します。
- 「このアカウントはすでに接続されています」と出る場合、そのアカウントはすでにサイドバーにあります。新しいパスワードの入力などは、代わりに **⋯ → 編集**から変更してください。
- 接続に失敗する場合は、サーバー URL が `https://` で始まり、サインインするウェブページではなく CalDAV アドレスを指しているか確認してください。Mitra がサーバーに送るすべてのリクエストを見るには、[ログレベル](../logging.md)を `debug` に設定します。
- Mitra を更新した後にカレンダーの表示がおかしい場合は、その **⋯** メニューの**項目を再インポート**を使います。同期はサーバーで変更された分だけを取得するので、変わらなかった項目は二度と読み直されません。再インポートはすべてを読み直します。[カレンダーを再インポートする](../calendars.md#re-import-a-calendar)を参照してください。
