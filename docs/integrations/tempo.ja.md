[Tempo](https://www.tempo.io/) は Jira 向けのタイムトラッキングアプリです。Mitra は、Jira課題に記録した作業時間である **ワークログ** を、時刻付きの項目としてカレンダーに表示します。その時間が費やされた会議やタスクの隣に並びます。

ワークログは双方向に同期されます。項目を移動・リサイズすれば作業した日時と長さが変わり、説明を編集すればワークログのメモが変わり、削除すればワークログごと消え、新しい項目を作れば新たに時間を登録できます。

アプリから 2 つの API トークンで接続します。サーバー側で設定するものはありません。

## タイムシートを接続する

Mitra には Tempo のトークンと Atlassian のトークンの 2 つが必要です。Tempo が時間を持ち、Jira が課題とあなたが誰かを知っています。

1. Tempo API トークンを作成します。Jira で Tempo の **Settings**（歯車アイコン）→ **Data Access** → **API integration** を開き、**New Token** を選んで「Mitra」と名付け、トークンをコピーします。
2. [id.atlassian.com/manage-profile/security/api-tokens](https://id.atlassian.com/manage-profile/security/api-tokens) の **Create API token** で Atlassian API トークンを作成し、コピーします。2 つのトークンは同じ Jira ユーザーで作成してください。
3. Mitra でサイドバー下部の **連携を追加** を選び、**Tempo** を選択して、次を入力します。
   - **サイト URL**：`https://your-company.atlassian.net` のような Atlassian のアドレス。
   - **Tempo API トークン**：手順 1 のトークン。
   - **Atlassian アカウントのメールアドレス**：Atlassian アカウントのメールアドレス。
   - **Atlassian API トークン**：手順 2 のトークン。
4. **接続** を押します。**My worklogs** というカレンダーが 1 つ表示されます。
5. 有効なままにして **保存** を押します。

Tempo にはアプリから呼び出せる頻度の上限があるため、Mitra は約 1 分ごとに同期します（[同期の仕組み](README.md#how-syncing-works)を参照）。

## ワークログの見え方

項目のタイトルは、時間が記録された Jira課題、つまりそのキーと要約です。

```text
ACME-1234 Code review for auth migration
```

ワークログのメモは項目の説明になります。Tempo 本体のアプリでも同じように表示されます。課題がその時間を何に使ったかを示し、メモは「Review」のような作業ラベルか、「Working on work item ACME-1234」のような Jira が代わりに書いた文字列であることが多いためです。

タイトルは課題のものなので、保存済みのワークログでは編集できません。カレンダーの項目を編集したからといって、Mitra が Jira課題の名前を変えることはないからです。何をしたかは説明を編集してください。課題が削除された、または見られなくなったなどで Jira が課題名を返せない場合、タイトルは `#` と課題 ID になりますが、項目はそのまま使えます。

Tempo はワークログをタイムゾーンなしの単純な時刻として保存します。Mitra はあなたの Jira プロフィールのタイムゾーンで読み取るので、Tempo と同じ時刻に表示されます。

開始時刻を無効にしている Tempo サイトもあります。そこでは、その日のワークログはすべて同じ時刻開始になり重なって表示されますが、長さは正確です。

## Mitra から時間を登録する

**My worklogs** で時刻付きの項目を作成し、タイトルのどこかに Jira課題キーを入れます。

| 入力する内容 | 記録先 |
| --- | --- |
| `ACME-1234 Team standup` | `ACME-1234` |
| `Investigating ACME-1234 regression` | `ACME-1234` |
| `ACME-1234` | `ACME-1234` |

Mitra は閲覧できる Jira プロジェクトと照合してキーを確認します。タイトルに該当するキーがない、または Jira にその課題がない場合、Mitra は何も登録せず、理由を知らせます。

ワークログのメモは説明に書いた内容で、説明を空にした場合は入力したタイトル全文になります。登録が済むと、タイトルは課題のキーと要約に置き換わります。この置き換えは登録時の一度だけなので、タイトルは書いている間は編集できて、あとは編集できません。

> [!TIP]
> 以前記録した課題に再度時間を登録するには、その項目を複製します。<kbd>Alt</kbd>（Mac では <kbd>⌥</kbd>）を押しながら新しい時刻へドラッグするか、エディターの **⋯** メニューで **複製** を選びます。

## ワークログを変更する

移動、リサイズ、削除、説明の編集はそのまま Tempo に反映されます。知っておくべき点がいくつかあります。

- ワークログはその課題に紐づいたままです。Tempo はワークログを別の課題へ移せないため、別の場所に時間を記録したい場合は、項目を削除して正しいキーで新しく作成してください。
- Mitra がワークログを変更するとき、請求可能時間や作業属性など、Tempo 固有の詳細は保持されます。
- Tempo でタイムシート期間がクローズまたは承認済みの場合、その期間内でのワークログの追加、変更、削除は拒否されます。

課題を Jiraで開くには、エディターの **⋯** メニューで **Jiraで開く** を選びます。

## ワークログに保存できないもの

ワークログは 1 つの課題に記録された、1 日の中のひと続きの時間です。そのため Tempo のカレンダーには時刻付きの項目しか入りません。終日項目、繰り返し、リマインダー、場所、参加者、[添付ファイル](../attachments.md)、関連付け、予定あり・空き、公開範囲、[対応可能時間](../availability.md)はありません。Mitra はワークログでこれらのフィールドを隠します。

## トラブルシューティング

- Mitra が「Tempo rejected the API token」と表示する場合、新しい Tempo API トークンを作成し、アカウントの **⋯ → 編集** で入力してください。
- Mitra が「Jira rejected the e-mail and API token」と表示する場合、そのメールアドレスが API トークンを作成した Atlassian アカウントのものか確認してください。
- ワークログの時刻がずれて表示される場合、Jira プロフィールのタイムゾーン（**Account settings** → **Time zone**）を確認してください。変更後は **My worklogs** の **⋯** メニューで **項目を再インポート** を使うと、既存のワークログも移動します。
- 毎日同じ時刻にワークログが重なって表示される場合、Tempo サイトで開始時刻が無効になっています。時間の長さ自体は正確です。
