میترا وقتی نسخه‌ای جدیدتر از آنچه اجرا می‌کنید وجود داشته باشد به شما خبر می‌دهد. هرگز خودش را به‌روز نمی‌کند: گرفتن نسخه جدید با خود شماست.

## نشانگر به‌روزرسانی

وقتی چیزی جدیدتر وجود داشته باشد، نقطه‌ای کوچک روی نشان نوار کناری ظاهر می‌شود. روی نام نمونه خود کلیک کنید تا **درباره** باز شود، که نسخه و کامیتی را که اجرا می‌کنید و پیوندی به تازه‌ها نشان می‌دهد. **کپی** در آنجا جزئیات نسخه را کپی می‌کند، که گزارش یک باگ به آن نیاز دارد.

**تازه‌ها**، در [پالت دستورها](shortcuts.md#command-palette)، تغییرات همه نسخه‌ها را فهرست می‌کند. پس از به‌روزرسانی سرور، میترا در هر زبانه‌ای که از پیش باز بوده از شما می‌خواهد **بارگیری مجدد برای تکمیل به‌روزرسانی** را انجام دهید.

اگر یک انتشار (`latest`، `0.6` یا یک نسخه دقیق) اجرا می‌کنید، شما را به جدیدترین انتشار راهنمایی می‌کند. اگر ایمیج `dev` را اجرا می‌کنید، به جدیدترین کامیت‌های `main` اشاره می‌کند و می‌گوید چقدر جلوتر هستند.

## بررسی چه چیزی می‌فرستد

سرور، نه مرورگر شما، چند بار در روز از GitHub می‌پرسد آیا چیز جدیدتری هست. این درخواست چیزی درباره نمونه شما جز آنچه هر درخواستی دارد در بر ندارد: نشانی IP شما و نسخه در حال اجرا در user agent. بدون تله‌متری، بدون شناسه و بدون شمارش.

اگر سرور نتواند به GitHub برسد، یک بار آن را ثبت می‌کند و پس از آن ساکت می‌ماند.

برای خاموش کردن کامل بررسی، `MITRA_UPDATE_CHECK` را روی `off` بگذارید (`false`، `0` و `no` هم کار می‌کنند):

```yaml
environment:
  MITRA_UPDATE_CHECK: 'off'
```

## انتخاب برچسب ایمیج

برچسب تعیین می‌کند با چه اشتیاقی به نسخه‌های جدید بروید.

| برچسب | آنچه می‌گیرید |
| --- | --- |
| `latest` | جدیدترین انتشار. |
| `0.6` | جدیدترین انتشار `0.6.x`: رفع اشکال، اما بدون نسخه فرعی جدید. |
| `0.6.0` | دقیقاً همان نسخه. |
| `dev` | آخرین کامیت `main`، برای امتحان کردن چیزها پیش از انتشار. |

تا پیش از ۱٫۰، یک نسخه فرعی جدید (۰٫۶ به ۰٫۷) می‌تواند چیزهایی را که به آن‌ها تکیه دارید تغییر دهد. اگر ترجیح می‌دهید خودتان زمانش را انتخاب کنید، از `0.6` استفاده کنید و هر وقت آماده بودید جلو بروید. همه برچسب‌ها در [GitHub](https://github.com/a11delavar/mitra/pkgs/container/mitra) فهرست شده‌اند.

## به‌روزرسانی میترا

ایمیج جدید را بگیرید و کانتینر را دوباره بسازید:

```bash
docker compose pull
docker compose up -d
```

داده‌های شما در پوشه نصب‌شده است، پس می‌مانند. اگر نسخه جدید پایگاه‌داده را تغییر دهد، میترا هنگام راه‌اندازی آن را به‌روز می‌کند و هیچ‌وقت لازم نیست خودتان به آن دست بزنید. ابزارهایی مانند [Watchtower](https://containrrr.dev/watchtower/) می‌توانند این کار را به‌صورت زمان‌بندی‌شده برایتان انجام دهند.

اینکه کدام نسخه را می‌گیرید به [برچسب ایمیج](#choose-an-image-tag) شما بستگی دارد. پیش از رفتن به یک نسخه فرعی جدید، خواندن [یادداشت‌های انتشار](https://github.com/a11delavar/mitra/releases) ارزش دارد.
