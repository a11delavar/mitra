---
title: 로깅
description: MITRA_LOG_LEVEL로 Mitra가 남기는 로그의 양을 정하고, 어떤 문제에 어떤 수준이 도움이 되는지 알아보세요.
---

Mitra는 표준 출력으로 로그를 남기므로 `docker compose logs`에서 모든 것을 볼 수 있습니다.

```bash
docker compose logs -f mitra
```

정상적인 서버는 일부러 조용합니다. 기본적으로 중요한 것만 기록합니다. 문제를 추적하는 동안에는 수준을 올리고, 끝나면 다시 내리세요.

## 수준 설정하기

```yaml
environment:
  MITRA_LOG_LEVEL: 'debug'
```

각 수준은 그보다 조용한 수준의 내용을 모두 포함합니다.

| `MITRA_LOG_LEVEL` | 기록되는 내용 |
| --- | --- |
| `error` | 실패만 기록합니다. |
| `warn` | Mitra가 우회한 문제도 기록합니다. 전달하지 못한 알림, 응답하지 않은 지오코더, 연결할 수 없었던 로그인 제공자 같은 것들입니다. |
| `info` *(기본값)* | 일상적으로 중요한 것도 기록합니다. 시작, 로그인, 계정 연결, 제공 업체에서 동기화된 변경 사항, 보낸 알림입니다. |
| `debug` | 모든 요청과 그 상태 및 소요 시간, 각 동기화, 사람들이 Mitra를 열고 닫으면서 동기화가 빨라지거나 느려지는 시점, 세션, 항목 편집, CalDAV 서버와 주고받은 내용도 기록합니다. |
| `trace` | 모든 데이터베이스 쿼리와 캘린더 원본 데이터도 기록합니다. 양이 아주 많습니다. |

Mitra는 시작할 때 실행 중인 수준을 기록합니다.

> [!NOTE]
> 비밀번호, 토큰 등 비밀 정보는 어떤 수준에서도 기록되지 않습니다. 그래도 `debug`와 `trace`에는 항목 제목과 캘린더 데이터가 나올 수 있으니, 로그를 공유하기 전에 살펴보세요.

## 어떤 수준을 쓸지

- 캘린더가 동기화되지 않을 때는 `debug`가 각 동기화와 CalDAV 및 Notion으로 가는 요청을 보여 줍니다.
- 알림이 오지 않을 때는 `info`가 이미 알림을 보낼 때마다 기록하고, `debug`는 각 전달 시도와 제외된 기기를 더해 보여 줍니다.
- 오류 페이지가 보일 때는 `error`에 스택 트레이스와 함께 기록되며, 기본값인 `info`에도 포함됩니다.
- 제공 업체가 보낸 내용을 정확히 봐야 할 때는 `trace`가 원본 데이터와 데이터베이스 쿼리를 더해 보여 줍니다. 잠깐만 켜 두세요.
