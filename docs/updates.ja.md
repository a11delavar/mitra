実行中のバージョンより新しいバージョンがあると、Mitraがお知らせします。Mitraが自分で更新することはありません。新しいバージョンを取得するかどうかは、あなたが決めます。

## 更新インジケーター

新しいバージョンがあるときは、サイドバーのロゴに小さなドットが表示されます。サーバー名をクリックして **バージョン情報** を開くと、実行中のバージョンとコミット、そして新機能へのリンクが表示されます。そこにある **コピー** を押すとバージョンの詳細がコピーされます。バグ報告にはこの情報が必要です。

[コマンドパレット](shortcuts.md#command-palette)にある **新機能** には、すべてのバージョンの変更点が一覧表示されます。サーバーが更新されたあとは、更新前から開いていたタブに **再読み込みして更新を完了** が表示されます。

リリース版(`latest`、`0.6`、または特定のバージョン)を使っている場合は、最新のリリースを案内します。`dev`イメージを使っている場合は、`main`の最新コミットを案内し、それらがどれだけ先行しているかもお知らせします。

## 確認で送信されるもの

サーバー(ブラウザーではありません)が、1日に数回、GitHubへ新しいバージョンがあるかどうかを問い合わせます。このリクエストには、どんなリクエストにも含まれる情報、つまりIPアドレスとユーザーエージェントに含まれる実行中のバージョン以外、サーバーに関する情報は一切含まれません。テレメトリも識別子もカウントもありません。

サーバーがGitHubに接続できない場合は、一度だけログに記録し、その後は何も出力しません。

この確認を完全にオフにするには、`MITRA_UPDATE_CHECK`を`off`に設定します(`false`、`0`、`no`でも構いません)。

```yaml
environment:
  MITRA_UPDATE_CHECK: 'off'
```

## イメージタグを選ぶ

タグは、どのくらい積極的に新しいバージョンへ移行するかを決めます。

| タグ | 取得できる内容 |
| --- | --- |
| `latest` | 最新のリリース。 |
| `0.6` | 最新の`0.6.x`リリース。修正は入りますが、新しいマイナーバージョンにはなりません。 |
| `0.6.0` | そのバージョンそのもの。 |
| `dev` | `main`の最新コミット。リリース前の機能を試すためのものです。 |

1.0までは、新しいマイナーバージョン(0.6から0.7など)で、あなたが使っている機能が変わる可能性があります。移行するタイミングを自分で決めたい場合は、`0.6`を使い、準備ができたら切り替えてください。すべてのタグは[GitHub](https://github.com/a11delavar/mitra/pkgs/container/mitra)に一覧があります。

## Mitraを更新する

新しいイメージをプルして、コンテナを再作成します。

```bash
docker compose pull
docker compose up -d
```

データはマウントされたフォルダーにあるので、そのまま残ります。新しいバージョンでデータベースが変わる場合は、起動時にMitraが自動で更新するので、自分で触る必要はありません。[Watchtower](https://containrrr.dev/watchtower/)などのツールを使えば、スケジュールを決めてこの作業を自動で行えます。

どのバージョンになるかは[イメージタグ](#choose-an-image-tag)で決まります。新しいマイナーバージョンに移る前に、[リリースノート](https://github.com/a11delavar/mitra/releases)を読んでおくと安心です。
