میترا همه چیز را در یک پوشه نگه می‌دارد: `/app/data` درون کانتینر، که اگر مطابق [شروع کار](README.md#install-mitra) پیش رفته باشید روی میزبان همان `~/mitra` است. از این پوشه پشتیبان بگیرید تا از کل نمونه پشتیبان گرفته باشید. سرور پایگاه‌داده‌ای برای تخلیه نیست و فایل پیکربندی‌ای برای جدا کردن وجود ندارد.

> [!CAUTION]
> برای بخشی از آنچه در میترا نگه می‌دارید، این پوشه تنها نسخه است. هر مورد در یک [تقویم میترا](integrations/mitra.md) همین‌جا و فقط همین‌جا زندگی می‌کند. حساب‌ها و نشست‌های ورود، اطلاعات ورود حساب‌های متصل، تنظیمات، رنگ و ترتیب و نام تقویم‌ها، [زمان‌های در دسترس](availability.md)، ترتیب کارها، برخی پیوندهای میان موارد و کلیدی که [یادآورهای](reminders.md) دستگاه‌هایتان به آن وابسته است هم همین‌طورند. اگر پوشه را از دست بدهید، یک ارائه‌دهنده می‌تواند رویدادها و کارهایش را به شما برگرداند، اما هیچ چیز دیگری را نه.

## پشتیبان‌گیری

هر ابزاری را که از پیش دارید به سمت پوشه بگیرید: [restic](https://restic.net/)، [Borg](https://www.borgbackup.org/)، `rsync`، یک اسنپ‌شات از سیستم فایل یا ماشین مجازی، یا یک آرشیو ساده.

امن‌ترین نسخه، نسخه‌ای است که هنگام متوقف بودن میترا گرفته می‌شود:

```bash
docker compose stop mitra
restic backup ~/mitra        # or: tar czf mitra-backup.tar.gz -C ~/mitra .
docker compose start mitra
```

اگر نمی‌توانید آن را متوقف کنید، کپی پوشه در حین اجرای میترا معمولاً مشکلی ندارد، چون SQLite از پس آن خوب برمی‌آید. اسنپ‌شات سیستم فایل یا ماشین مجازی بدون متوقف کردن چیزی، یک نسخه یکدست به شما می‌دهد.

## بازیابی

میترا را متوقف کنید، پوشه را سر جایش برگردانید و دوباره آن را راه‌اندازی کنید:

```bash
docker compose stop mitra
restic restore latest --target ~/mitra        # or extract your archive there
docker compose start mitra
```

پوشه را یکجا بازیابی کنید. فایل‌های آن به هم تعلق دارند و آمیختن فایل‌های روزهای مختلف می‌تواند نمونه را خراب کند. پشتیبان یک نسخه قدیمی‌تر روی ایمیج جدیدتر بدون مشکل بازیابی می‌شود، چون میترا هنگام راه‌اندازی پایگاه‌داده‌اش را به‌روز می‌کند.

## آنچه پشتیبان پوشش نمی‌دهد

رویدادها و کارهای حساب‌های متصل، مانند سرور [CalDAV](integrations/caldav.md)، [Google Calendar](integrations/google.md) یا [Notion](integrations/notion.md)، نزد همان ارائه‌دهندگان می‌مانند. پشتیبان شامل نسخه میترا از آن‌هاست و پس از بازیابی، میترا دوباره آن‌ها را همگام می‌کند.

متغیرهای محیطی شما در `compose.yaml` یا فایل `.env` شما هستند، نه در پوشه داده. آن‌ها را هم امن نگه دارید، در سیستم کنترل نسخه یا مخزن رازهایتان.
